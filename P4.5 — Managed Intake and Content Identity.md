# P4.5 — Managed Intake and Content Identity

## Purpose

External files are evidence-bearing source occurrences, not Atlas working storage. Before semantic inspection or durable Work, Atlas acquires stable source bytes into an Atlas-controlled intake area. The original source is never renamed or rewritten by this stage.

## Intake sequence

`source occurrence → Artifact identity → verify format → managed acquisition/content identity → inspect → classify → Work → representations → Knowledge`

Managed acquisition is deterministic runtime work, not model judgement.

## Content identity

The canonical identity of acquired bytes is SHA-256. Atlas streams the source through the governed local-source kernel, writes a temporary managed file, verifies source stability, fsyncs the copy, and atomically establishes a canonical storage name.

Canonical storage names are:

`sha256-<full-content-sha256>.<detected-extension>`

The extension is selected from structural format detection where possible; the original filename is never used as identity.

## Duplicate handling

If the same bytes are presented later under another path or filename, Atlas links the new source occurrence to the existing managed Artifact. It does not create another managed content object.

One managed content Artifact may therefore have many source occurrences. Exact duplicate collapse is byte-identity only. Different bytes are never automatically treated as the same revision or document.

## Provenance

A new managed Artifact records `relation: managed_copy`, its source Artifact parent, content SHA-256, detected format, original display name, original root and original relative path. Additional exact-duplicate occurrences are preserved in the durable managed-content/source link table rather than rewriting the Artifact's creation provenance.

## Workflow handoff

When managed intake is configured, `DeterministicIntakeWorkflow` owns the mandatory pre-semantic chain: `artifacts.verify_format → artifacts.acquire_managed → artifacts.inspect`. All three stages are registered governed capabilities, but the runtime selects this chain; the model cannot omit, reorder or bypass it. The resulting managed Artifact and inspection are then handed to semantic classification and responsibility routing.

If an already-classified managed content Artifact is presented again, intake records the new source occurrence as `reused_existing_content` and reuses the existing responsibility/Work reference instead of creating duplicate expensive derivation work.

## Naming rule

Storage name, identity and display metadata are separate concerns:

- identity: content SHA-256 / Artifact ID
- storage filename: deterministic safe canonical name
- display name: human-facing metadata that can later be normalized semantically

Changing or correcting a display name must never move or change the underlying managed object.

## Knowledge generation safety

Candidate and active generations are frozen. New indexing creates a building generation; when an active generation exists, the building generation starts with the active passage memberships and adds new material there. `knowledge.index` refuses explicit writes to candidate or active generations.

## Non-goals

This slice does not decide document-family equivalence, revisions, semantic field normalization, table providers, visual providers or vector retrieval. Those remain evidence-driven follow-on work.


## Governed capabilities

- `artifacts.verify_format` — deterministic libmagic signature/MIME verification and canonical extension selection.
- `artifacts.acquire_managed` — stable copy + SHA-256 content identity + exact dedupe + canonical `sha256-<digest>.<verified-ext>` custody naming.
- `artifacts.inspect` — bounded structural inspection of the managed Artifact.

`DeterministicIntakeWorkflow.available()` is the explicit runtime stage catalog for this boundary. The intake runtime executes the registered stages in that declared order before semantic classification and records their occurrence IDs. Model output begins only after this custody workflow completes.
